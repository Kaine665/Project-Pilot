## Phase ① 轻量 PRD

### 一句话目标

用户在 **任务** 壳内，**10 秒内**能回答：「我现在要管的是 **手头待办**、**事件触发规则**，还是 **定时计划**？」并在该子页 **一次看到主操作入口**（新建 / 核心列表），不被次要说明淹没。

### 各子路由：主任务 · 次要任务 · 空状态


| 路由                           | 主任务（Primary job）                     | 次要任务（Secondary）                   | 空状态（本期文案意图）                                                           |
| ---------------------------- | ------------------------------------ | --------------------------------- | --------------------------------------------------------------------- |
| `/workspace/tasks/todos`     | 按当前视图浏览与处理待办；拖拽/改状态；打开抽屉编辑或派发 Agent  | 切换视图（今天/即将/看板/全部/已完成）；搜索与筛选；批量操作  | 无数据：说明「当前项目/筛选下无待办」+ 引导 **新建任务**（与现实现一致即可，可强化一句场景）                    |
| `/workspace/tasks/triggers`  | 查看规则是否启用；**新建规则**；对单条规则：检查 / 编辑 / 启停 | 阅读「版本边界」说明                        | 无规则：插画/图标 + **还没有事件触发规则** + 一句价值说明 + **新建触发规则**                       |
| `/workspace/tasks/schedules` | 查看计划与上次运行；**新建定时任务**；启停 / 手动触发 / 编辑  | 展开单条的执行历史；创建表单内选 Agent 消息 vs Todo | 无计划：**暂无定时任务** + Cron 能做什么的一句 + **新建**（与现 `AgentSchedulesPanel` 空态对齐） |


### 跨页一致规则（壳内同构）

1. **顶栏**：仅由 `tasks/layout.tsx` 提供——标题「任务」+ 副标题 + 三个 `NavLink`；不在子页重复 H1「任务」。
2. **主内容区第一视线**：每子页进入后，**首屏主内容顶部**应出现 **本页主标题或工具条**（二选一或组合），且 **主按钮（新建）** 位置 **统一为「工具条行右端」或「标题行右侧」**（实现时三页同一套模式，避免一左一右）。
3. **宽度与密度**：
  - **待办**：允许 **全宽**（看板三列需要横向空间）。
  - **触发 / 定时**：同属「规则列表」心智，采用 **同一 `max-width` 与水平 padding 策略**（**单列主内容、不做侧边统计区**；现状触发仍带 Rules/Enabled 大卡、定时偏窄——**目标态对齐为一条垂直流**，见 Layer 1；Paper 先画线框）。
4. **开发者开关**：关闭「任务触发 / 定时运行」时，Tab 隐藏 + 重定向至待办——IA 不假设用户总能看到三 Tab。

### 本期非目标（避免 scope 膨胀）

- 不改 API、不改触发/定时的业务规则文案以外的**逻辑**。
- 不在壳内新增第四 Tab。
- 不要求 Paper 与代码像素级一致；以 **区块优先级与对齐** 为准。

### 产品定案：不要「统计仪表盘」

规则数、定时条数通常 **个位数～少量**，**不需要** Rules/Enabled 大卡、顶部「共 N 条 / M 启用」等汇总块；信息以 **列表 + 行内状态（启用/禁用、上次运行）** 为主，界面更干净。任务壳下 **触发 / 定时** 两页 **都不做**这类统计 UI（独立全页路由若仍保留标题区文案中的计数，改版时可再收敛，以壳内体验为准）。

## Phase ② `frontend-design` Layer 1

### 1. Visual thesis（一句）

在现有 **shadcn + zinc + Tailwind** 下，任务壳是 **冷静工具台**：**少装饰性卡片壳、强标题与列表节奏**；主色按钮与选中 Tab 延续全局 zinc 反色，**不**为子页引入第二套品牌色（Paper 里用过的青绿仅作探索，代码层以设计系统为准）。

### 2. Content plan（自上而下 · 一级区块）

**共用壳（layout，已有）**

1. 页眉：图标 + 标题「任务」+ 副标题
2. 分段导航：待办 | 任务触发 | 定时运行

**子页 A — 待办**

1. **工具条行**：视图切换（pill/segmented）| 搜索 | 筛选（优先级 / Agent / 逾期）| **新建任务**（右对齐或整行 flex end 分组）
2. **主工作区**：看板三列 **或** 列表/今日等（随视图变，占满剩余高度）
3. **次要**：批量模式条（出现时顶在列表上或吸底，不抢首屏）

**子页 B — 任务触发（`tasksHub`）**

1. **工具条行**：左侧 **一页一句说明**（可替代大标题）+ 右侧 **新建触发规则**
2. **版本边界**说明条（全宽、弱背景）
3. **规则列表**：卡片列表；单卡内：标题区 → 条件 chips → 操作 → 触发动作 → 最近运行

**子页 C — 定时运行（`showPageHeader=false`）**

1. **工具条行**：左侧 **短标题「定时任务」+ 可选一行说明**（与触发页工具条 **同高、同 padding**）+ 右侧 **新建定时任务**
2. **计划列表**：与现 `ScheduleRow` 一致的信息优先级：类型 chip → cron → 标签 → 摘要 → 上次运行 → 操作图标列

### 3. Interaction plan（2～3 条，具体）

1. **Tab**：与 URL 同步；切换 Tab **不丢**各子页滚动位置（若现状未做，实现阶段再评估，IA 仅记期望）。
2. **待办**：看板拖拽跨列后 **立即反馈**列计数（若已有则保持）；点卡片打开抽屉，抽屉内主按钮区固定可预期。
3. **触发 / 定时**：列表行 **悬停**时次要操作更明显（边框或背景），与 `frontend-design` 可访问性要求一致；**新建**展开表单时，表单与列表的 **焦点顺序** 合理（不跳读）。
