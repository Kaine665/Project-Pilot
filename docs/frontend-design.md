# 前端设计：对话 + 产出物侧栏

> **关联文档**: `docs/ai-task-workflow.md`（AI 会话工作流设计）

## 设计背景

原有 UI 把"生成计划"、"AI 对话"、"开始执行"三个按钮平铺，用户可以随意点击，不符合 5 阶段工作流的线性逻辑。实际上整个工作流的主载体就是 AI 对话，每个阶段的产出物（任务理解、计划、执行结果）应当从对话中提取出来，放在可以随时查看的位置。

## 整体布局

```
┌──────────────────────────┬───────────────────┐
│                          │                   │
│  AI 对话                  │  产出物侧栏        │
│                          │                   │
│  ┌─ AI ───────────────┐  │  ┌─────────────┐  │
│  │ 我理解这个任务是…   │  │  │ 📋 任务理解  │  │
│  └────────────────────┘  │  │ "在ELApp中…" │  │
│                          │  │ [重新理解]    │  │
│  ┌─ 用户 ─────────────┐  │  └─────────────┘  │
│  │ 对                  │  │                   │
│  └────────────────────┘  │  ┌─────────────┐  │
│                          │  │ 📝 执行计划  │  │
│  ┌─ AI ───────────────┐  │  │ 1. 创建组件  │  │
│  │ 计划如下…           │  │  │ 2. 添加路由  │  │
│  └────────────────────┘  │  │ [重新规划]   │  │
│                          │  └─────────────┘  │
│  ┌─ AI ───────────────┐  │                   │
│  │ 开始执行步骤 1…     │  │  ┌─────────────┐  │
│  │ [Read file.ts]      │  │  │ 📦 执行结果  │  │

│  └────────────────────┘  │  └─────────────┘  │

└──────────────────────────┴───────────────────┘
```

- **左侧**：标准 AI 对话界面，全程不变
- **右侧**：产出物侧栏，卡片随阶段推进依次出现

## 侧栏卡片

### 1. 任务理解卡片（Phase 1-2）

AI 在对话中完成四要素确认后，输出结构化的任务理解摘要。

**AI 输出格式约定**：

````
```json:understanding
{
  "project": "ELApp",
  "action": "从 Supabase 拉取历史反馈数据，汇总分析后给出优化建议",
  "goal": "用户反馈功能优化",
  "deliverable": "分析报告 + 代码优化建议"
}
```
````

**卡片展示**：

```
┌─────────────────────────┐
│ 📋 任务理解              │
│                         │
│ 项目：ELApp             │
│ 做什么：从 Supabase 拉取 │
│   历史反馈数据做汇总分析  │
│ 为什么：用户反馈功能优化  │
│ 交付物：分析报告 +       │
│   代码优化建议            │
│                         │
│              [重新理解 ↺] │
└─────────────────────────┘
```

**操作**：
- `[重新理解]`：往对话中发送"请重新分析这个任务"，AI 重走 Phase 1-2，新产出替换旧卡片

### 2. 执行计划卡片（Phase 3）

AI 在对话中产出计划，使用已有的 `json:plan` 格式。

**AI 输出格式约定**：已有，见 `plan-extractor.ts`

**卡片展示**：

```
┌─────────────────────────┐
│ 📝 执行计划  v2          │
│                         │
│ 1. □ 创建反馈列表组件    │
│ 2. □ 添加 API 接口      │
│ 3. □ 接入 Supabase 查询 │
│ 4. □ 添加路由和导航      │
│                         │
│ 风险：Supabase 分页查询  │
│   可能需要调整           │
│                         │
│    [重新规划 ↺]          │
└─────────────────────────┘
```

**操作**：
- `[重新规划]`：往对话中发送"请重新制定计划"

**说明**：
- 计划卡片没有"开始执行"按钮。是否执行由 AI 在对话中自行判断（低风险直接开始）或向用户确认（高风险时在对话中询问）
- 执行开始后，AI 自行创建 git 分支，不需要用户手动操作

### 3. 执行状态卡片（Phase 4 进行中）

AI 开始执行后，侧栏显示实时执行状态。

**卡片展示**：

```
┌──────────────────────────┐
│ ⚙️ 执行中                │
│                          │
│ 分支：task/task-123-abc  │
│                          │
│ 1. ✅ 创建反馈列表组件    │
│ 2. 🔄 添加 API 接口      │
│ 3. □ 接入 Supabase 查询  │
│ 4. □ 添加路由和导航       │
│                          │
│ 已改动文件：              │
│  + src/components/FB.tsx │
│  ~ src/app/api/route.ts  │
└──────────────────────────┘
```

**数据来源**：
- 分支名：AI 创建分支时通过约定格式输出
- 步骤进度：AI 在执行过程中更新
- 改动文件：从工具调用（Write、Edit）中提取

### 4. 执行结果卡片（Phase 5）

执行完成后，状态卡片变为结果卡片。

**AI 输出格式约定**：

````
```json:result
{
  "status": "completed",
  "branch": "task/task-123-abc",
  "summary": "已完成反馈历史功能，包含列表页和详情页",
  "files_changed": [
    { "path": "src/components/FeedbackList.tsx", "action": "created" },
    { "path": "src/app/api/feedback/route.ts", "action": "created" },
    { "path": "src/navigation/index.ts", "action": "modified" }
  ],
  "stats": { "added": 3, "modified": 1, "deleted": 0 }
}
```
````

**卡片展示**：

```
┌──────────────────────────┐
│ ✅ 执行完成               │
│                          │
│ 分支：task/task-123-abc  │
│                          │
│ 已完成反馈历史功能，      │
│ 包含列表页和详情页        │
│                          │
│ 改动文件（4）：           │
│  + FeedbackList.tsx      │
│  + feedback/route.ts     │
│  ~ navigation/index.ts   │
│                          │
│ [合并分支] [放弃分支]     │
└──────────────────────────┘
```

**操作**：
- `[合并分支]`：调用 `/api/git` 合并，完成后卡片变为"已合并"状态
- `[放弃分支]`：删除分支，卡片变为"已放弃"状态

## 侧栏空状态

会话刚打开、还没有对话时，侧栏显示引导：

```
┌──────────────────────────┐
│                          │
│     💬                   │
│                          │
│  发送消息开始任务流程      │
│                          │
│  AI 会自动：              │
│  · 理解任务上下文         │
│  · 制定执行计划           │
│  · 执行并报告结果         │
│                          │
└──────────────────────────┘
```

## 提取机制

所有侧栏卡片的数据都从 AI 对话输出中提取，统一使用带标签的 JSON 代码块：

| 标签 | 用途 | 提取器 |
|------|------|--------|
| `json:understanding` | 任务理解 | 新增 |
| `json:plan` | 执行计划 | 已有 `plan-extractor.ts` |
| `json:result` | 执行结果 | 新增 |

提取流程：
1. AI 在对话中输出带标签的 JSON 代码块
2. 前端流式解析时检测到标签，提取 JSON 数据
3. 数据保存到后端（如 `ai-understanding.json`），同时更新侧栏卡片
4. 对话中原始的 JSON 块可以折叠显示或替换为"已提取到侧栏"的提示

## 阶段转换

### AI 自行推进

大多数阶段转换由 AI 自行判断：
- Phase 1→2：AI 分析完四要素后自动进入提问/确认环节
- Phase 2→3：用户确认理解后，AI 自动产出计划
- Phase 3→4：AI 判断风险低时，自行创建分支开始执行
- Phase 4→5：执行完成后自动输出结果

### 需要用户介入的情况

- **Phase 2**：AI 有疑问时，在对话中提问，等用户回复
- **Phase 3→4**：AI 判断风险高时，在对话中明确询问"是否开始执行？"
- **Phase 5**：合并/放弃由用户在侧栏卡片上点击

### 用户主动回退

用户可以通过侧栏卡片上的按钮回退：
- `[重新理解]` → AI 重走 Phase 1-2，新的理解替换旧卡片
- `[重新规划]` → AI 重走 Phase 3，新的计划替换旧卡片

回退的实现方式：点击按钮 = 往对话里发一条预设消息，AI 收到后重新执行对应阶段。

## 侧栏第一张卡片：会话信息

会话信息（标题、状态）始终作为侧栏第一张卡片显示，不再有单独的顶部头部区域。原来顶部的描述编辑区域已移除——描述在创建时填写，之后只通过侧栏卡片展示标题和元信息。

```
┌─────────────────────────┐
│ 📋 查看历史反馈记录      │  ← 会话标题
│                         │
│ [待办] [进行中] [已完成]  │  ← 状态切换
└─────────────────────────┘
```

## 已移除的 UI 元素

- **"生成计划"按钮** — AI 在对话中自然产出计划
- **"AI 对话"按钮** — 对话始终可见，不需要切换
- **"开始执行"按钮** — AI 自行创建分支并执行
- **"计划"Tab** — 计划在侧栏卡片中展示
- **"验证产物"Tab** — 执行结果在侧栏卡片中展示
- **底部三按钮工具栏** — 操作按钮跟着侧栏卡片走
- **顶部头部区域** — 标题/描述/状态编辑移到侧栏会话信息卡片
- **上下拖拽分割线** — 不再需要（没有上下分区了）
- **AI execution 状态条** — 状态由侧栏卡片体现

## 与 ai-task-workflow.md 的关系

本文档是 `ai-task-workflow.md` 中定义的 5 阶段工作流的**前端实现方案**。工作流定义了 AI 的行为逻辑（prompt 层），本文档定义了用户看到和操作的界面。

> **术语说明**：前端代码中仍存在部分旧 Task 术语（如 `task-detail.tsx`、`task-list.tsx`），待逐步迁移为 Session。数据模型层已完成迁移，前端组件名暂不影响功能。

两者的对应关系：

| 工作流阶段 | 前端表现 |
|-----------|---------|
| Phase 1-2: 确定四要素 + 识别缺口 | 对话中进行，产出物提取到"任务理解"卡片 |
| Phase 3: 制定计划 | 对话中进行，产出物提取到"执行计划"卡片 |
| Phase 4: 执行 | 对话中实时展示工具调用，侧栏显示"执行状态"卡片 |
| Phase 5: 总结与合并 | 对话中展示总结，侧栏显示"执行结果"卡片，挂合并/放弃按钮 |
