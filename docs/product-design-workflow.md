# 产品 / 设计工作流（仓库根 · 单人 + Agent）

面向 **只有你一个人**、没有设计岗/产品岗同事时的做法：**你和 Agent 对话** 推进页面；**Figma、Superdesign、出稿类工具** 若需要，由 **Agent 去跑、去产出**，你不必自己会 Figma。

本流程是 **检查清单 + 节奏约定**：先保证「做对事」，再谈「好不好看」。**最终拍板永远是你**（选哪一版设计、算不算验收通过）。

---

## 默认节奏（最常发生的一条线）

典型顺序如下，可按需求删减，但建议 **不要跳过「你先说清楚要啥」和「你亲自走一遍验收」**。

1. **你用自然语言跟 Agent 说清**：这页给谁用、要完成什么任务、有没有参考站或气质偏好（冷静工具 / 偏品牌 / 高密度等）。可极短，不必写长文档。
2. **Agent 先出多角度的优秀方案**（推荐默认就要求）：例如 2～3 个不同布局或视觉方向的草稿（可用 Superdesign、静态 HTML 示意、分块说明等——**由 Agent 选用其能用的工具**，你不需要会 Figma）。
3. **你选方向**：指定「用 B 的信息架构 + A 的侧栏密度」这类组合也行；或让 Agent 基于你的反馈再收敛一轮。
4. **Agent 落实代码**：在仓库根目录的 `src/` 下改组件与样式；你给路径、文件或让 Agent 自己搜。
5. **你按真实任务走一遍验收**（见 §6）：截图只辅助沟通，**不算**唯一验收标准。

**不是要一开需求就长篇讨论。** 和 Agent 的对话可以就是 **几轮来回**；§1 的 bullet 也可以是你复制进聊天框的那几条。

---

## 何时走全流程 vs 快进

| 情况 | 建议 |
|------|------|
| 新页面、主导航/信息架构变化、多状态（空/错/载） | 走 **§1 → §6**（可与 Agent 口头压缩，但顺序建议保留） |
| 小修：对齐、间距、改一字、单组件 bug | 直接让 Agent 改代码；§1 可一句话带过 |

---

## 1. 对齐：问题与成功标准（你 → Agent 的输入）

**建议你发给 Agent 的最小信息**（几条 bullet 即可）：

- **谁在用**（例如「每天切模型、看上下文的我自己」）。
- **要完成什么任务**（动词 + 对象）。
- **怎样算成功**（1～3 条可观察标准，例如「三步内完成、不用查文档」）。
- **本轮不做啥**（非目标，防范围膨胀）。

**可交给 Agent**：根据你的草稿追问边界、补全遗漏状态、列假设；**你改完再进入出方案**。

---

## 2. 结构与任务流

**可由 Agent 起草，你修正**：

- **关键路径**：从进入到完成任务的步骤（3～7 步为宜）。
- **涉及界面**：区域/屏幕列表；复杂时让 Agent 用 ASCII / mermaid 也行。
- **分支状态**：空态、加载、错误、无权限里哪些与本需求相关。

**原则**：先稳定 **信息与任务顺序**，再堆视觉；否则 Agent 出再多稿也容易返工。

---

## 3. 交互与文案

**你与 Agent 分工**：

- 主/次操作、危险操作确认：让 Agent 按 §1～2 出第一版，你改语气与决策。
- 标题、按钮、错误提示：**最终用词你定**；Agent 可给备选。
- 无障碍：让 Agent 自检焦点、图标按钮命名等；**你相信不过就点一点、Tab 一下**。

可选用 **ui-ux-pro-max** 等只做「抽检提示词」，不必全文背诵。

---

## 4. 视觉与多方案（Agent 主笔，你选题）

**你不操作 Figma 时的默认做法**：

- 你把 **气质、参考链接、禁忌**（例如「不要大红大绿」「要跟现有顶栏一致」）说清楚。
- **请 Agent 主动给多个优秀方向**（布局或视觉至少有一个维度变化），而不是只给一稿。
- Agent 可用 **Superdesign、HTML 示意、分区域文字稿** 等你能看懂的产出；需要接 CLI/MCP 时由 Agent 侧执行，不要求你自己会设计软件。

**原则**：视觉服务于 **层级与可读性**；不为「实验对比」加与产品无关的装饰层。

---

## 5. 实现与一致性

**Agent**：在仓库里改代码，与站内已有页面组件、用语对齐；改动尽量 **一屏或一条主路径一个提交**，方便你回滚。

**你**：指定文件/路由，或说「跟某某页同一套按钮风格」；合并与否由你决定。

技术细节（Token、类名）由实现与迭代决定；**以 §4 选定方向可追溯为准**，本流程不绑死必须先改 `globals`。

---

## 6. 验收：任务 > 截图（必须你本人）

**必做**：

- **按 §1 的成功标准**，你自己操作走一遍主路径；记下卡点（犹豫、误点、看不懂）。
- **§2 里相关的** 空/错/载 至少 spot-check。

**可选**：缩窄窗口看严重布局问题；对比度/焦点让 Agent 查或你自己 devtools 看一眼。

**明确**：静态截图 **不能** 代替你走任务；截图只用于和 Agent 对齐画面。

---

## 和 Agent 对话时可用的短指令（示例）

- 「基于下面 §1，先给我 **3 个不同信息架构** 的草稿，再推荐一个。」
- 「在不动业务逻辑前提下，按 **B 方案** 改 `…/page.tsx`，并列出改了哪些文件。」
- 「用 ui-ux-pro-max 里 **无障碍 + 触控** 相关条目，扫一遍这页，只报 P0/P1。」

按你习惯改写即可；重点是 **你先约束目标，Agent 再展开方案与代码**。
