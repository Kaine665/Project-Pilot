# 上下文地图形态探索

这些草图由 Superdesign 生成，用来探索“项目上下文地图”到底可以长什么样。

当前不做最终决定，只比较不同数据结构带来的理解方式。

## 1. 树形目录

预览：https://p.superdesign.dev/draft/ce2ad8ac-bf5c-4107-b828-3b7be51ed394

核心表达：

> AI 对项目的理解目录。

适合呈现：

- 项目目标
- 稳定事实
- 关键决策
- 当前任务
- 约束
- 文档
- 代码区域
- 最近 Run
- 待审核 MemoryPatch

优点：

- 外行容易懂。
- 像文件目录，心智成本低。
- 适合做“项目上下文总目录”。

风险：

- 容易变成普通知识库。
- 不容易表达关系和流动。

## 2. 上下文矩阵

预览：https://p.superdesign.dev/draft/30fc6bce-fd8f-46b8-a7ed-3d32b666fedf

核心表达：

> 项目各区域的上下文健康度。

适合呈现：

- 横轴：Memory / Decision / Task / Constraint / Artifact / Run
- 纵轴：工程 / 产品 / 设计 / 增长 / 运营 / 商业
- 每个格子的数量、健康状态、缺失、过期、待审核

优点：

- 很适合扫全局。
- 能看出哪里上下文充足，哪里缺失。
- 适合管理复杂项目。

风险：

- 第一眼可能偏抽象。
- 如果数据太少，会显得空。

## 3. 时间线 / 接力轨迹

预览：https://p.superdesign.dev/draft/4a8ad15a-b9db-4917-ae07-70a4cd0b85de

核心表达：

> 项目理解如何随着每次 AI 工作演化。

适合呈现：

- Claude Code 读取 ContextPack
- AI 执行任务
- Cursor 继续接力
- Codex 查询决策
- 每次 Run 带来了哪些上下文变化

优点：

- 很能体现“不同 AI 工具接力”。
- 能解释为什么 PP 不是静态知识库。
- 对排查“AI 为什么这么做”有帮助。

风险：

- 日常管理效率可能不如表格或树。
- 时间线长了会变得嘈杂。

## 4. 证据链 / 上下文卡片分组

预览：https://p.superdesign.dev/draft/b435d095-108d-4775-8279-dbf69b359fbb

核心表达：

> 每个项目结论来自哪些证据，并影响哪些任务。

适合呈现：

- 当前定位
- 核心流程
- MCP 集成
- UI 假设
- 竞品风险
- 每个主题下的事实、决策、约束、任务和证据来源

优点：

- 很适合建立信任。
- 能看见“为什么 AI 认为这是事实”。
- 适合复杂决策和产品设计。

风险：

- 视觉上可能复杂。
- 如果做不好，会像一堆卡片。

## 5. 上下文表格清单

预览：https://p.superdesign.dev/draft/4d1a5cb3-f0bc-4efc-ad36-27de0eebeafd

核心表达：

> 把项目上下文当成数据库一样管理。

适合呈现：

- 类型
- 标题
- 项目区域
- 来源
- 可信度
- 最近使用
- 是否进入 ContextPack
- 关联任务
- 状态
- 待审核补丁

优点：

- 最可操作。
- 容易筛选、排序、批量处理。
- 适合成熟用户长期使用。

风险：

- 第一眼不够“地图”。
- 容易像后台管理系统。

## 6. 上下文泳道 / 线路图

预览：https://p.superdesign.dev/draft/02696daf-0b8e-4e0d-a931-72cec0c6d031

核心表达：

> 哪个 AI 工具在什么时候接过项目上下文，又留下了什么。

适合呈现：

- 横向：定位 / 设计 / 实现 / 验证 / 发布
- 纵向：Claude Code / Cursor / Codex / 用户
- 站点：Run / ContextPack / MemoryPatch
- 连线：上下文接力

优点：

- 很符合“接力”的产品隐喻。
- 能看见 harness 之间的关系。
- 比纯 MCP 日志更有画面感。

风险：

- 可能更像流程图，不像日常主界面。
- 对普通项目可能显得过重。

## 目前可以观察的方向

这些形态可能不是互斥关系，而是不同层级：

```text
树形目录：默认入口，帮用户理解项目上下文结构。
矩阵：全局健康度和缺口扫描。
时间线：解释项目上下文如何演化。
证据链：解释某个结论为什么成立。
表格清单：高级用户精确管理。
泳道线路图：展示 AI 工具之间的接力关系。
```

如果必须先猜一个更稳的主界面候选，我会把“树形目录 + 右侧详情 + 顶部健康摘要”作为最容易落地的版本，再把矩阵、时间线、证据链做成切换视图。
